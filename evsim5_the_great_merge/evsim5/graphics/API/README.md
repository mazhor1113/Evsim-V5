# Справочник графической подсистемы

Эта папка — документация для разработки симулятора. Здесь описано, **какой компонент использовать и для чего**. Рабочая реализация находится в `graphics/`, а не в этой папке.

## Быстрая карта проекта

| Модуль | Назначение |
|---|---|
| `graphics/backend/PyGame_backend.py` | Реализация графики через pygame: поверхности, текстуры, шрифты, события и вывод кадра |
| `graphics/protocols.py` | Контракты `GraphicsBackend` и `UIElement`, используемые для проверки типов |
| `graphics/ui/widgets.py` | `Rect`, текст, кнопки, переключатели, ползунок, контейнер `Panel` и окно `PopupWindow` |
| `graphics/ui/manager.py` | Регистрация дерева UI, отрисовка, поиск элемента под курсором, фокус и маршрутизация событий |
| `graphics/event.py` | Независимые от pygame типы событий `EventType` и `UIEvent` |
| `graphics/assets.py` | Загрузка текстур-заглушек, которые используются виджетами при отсутствии заданной текстуры |
| `graphics/canvas.py` | Массив RGB-пикселей симуляции и ускоренные numba-функции для его изменения |

## С чего начать

- Нужно добавить кнопку, подпись, ползунок или окно — см. [UI_GUIDE.md](UI_GUIDE.md).
- Нужно рисовать симуляцию, загружать текстуры или разбираться с поверхностями — см. [BACKEND_GUIDE.md](BACKEND_GUIDE.md).
- Нужно понять, почему событие мыши попало в конкретный элемент, — начни с `UIManager.handle_event()` и раздела о координатах в `UI_GUIDE.md`.

## Важные правила архитектуры

1. UI-виджеты не должны вызывать pygame напрямую. Они используют методы `GraphicsBackend`.
2. `UIManager` управляет деревом элементов и преобразованием координат; виджеты отвечают за собственное состояние и реакцию на события.
3. Прямоугольники дочерних элементов заданы в локальных координатах их контейнера.
4. Корневые обычные UI-элементы используют координаты `ui_surface`. Независимые корневые `PopupWindow` используют экранные координаты и рисуются на `main_surface`.
5. `Protocol` — описание ожидаемых методов для проверки типов, а не класс, от которого обязательно наследовать виджет.
6. Методы, имя которых начинается с `_`, являются внутренними деталями реализации. Симулятору обычно следует пользоваться публичными классами и методами.

## Что означает возвращаемый тип

- `-> None`: функция выполняет действие, но не возвращает полезного значения.
- `-> bool`: возвращает `True` или `False`.
- `-> Rect`: возвращает прямоугольник.
- `-> Rect | None`: может вернуть прямоугольник или `None`, если результата нет.
- `-> list[ChildContext]`: возвращает список контекстов дочерних элементов. Каждый контекст содержит сам элемент, смещение его координат и область отсечения.
- `-> tuple[int, int]`: возвращает пару целых чисел, например ширину и высоту.

Типы в исходном коде — часть контракта. Если меняется сигнатура метода, проверь вызовы и соответствующую документацию.
