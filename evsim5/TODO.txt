1. Система сценариев
    1.1 Выбор сценария через реестр.
        Когда сценариев станет несколько, можно создать:

        # scenarios/registry.py

        from scenarios.default import setup as default

        SCENARIOS = {    
            "default": default,
            }

        И выбирать сценарий по имени:

        scenario = SCENARIOS["default"]
        scenario.initialize(context)

        Позже выбор можно будет связать с меню, аргументами командной строки или конфигурационным файлом.
    
    1.2 
        scenarios/
            └── default/
                ├── __init__.py
                ├── setup.py
                ├── ui.py
                ├── world.py
                └── settings.py

        Файл world.py отвечает за создание мира в рамках конкретного сценария.

    1.3 Создать WorldController, скорее всего уже в движке. Он будет принимать контекст сценария и 
     выполнять работу с миром. Другие компоненты программы должны обращаться с миром через него.

    1.4 Контейнер ссылок для объектов ui и другой шляпы которая создается внутри функции, но должна 
     быть глобальной:

Я бы сохранил систему сценариев, но немного уточнил её назначение: сценарий должен описывать способ 
 создания начального состояния мира, а не управлять всем приложением.

В твоём случае важно разделить три уровня:
1. Приложение — окна, графический backend, UIManager, основной цикл.
2. Сценарий — определяет, какой мир создать и какие начальные условия ему задать.
3. Мир — конкретное состояние симуляции: массив ботов, параметры среды, ресурсы и другие данные, 
 которые могут быть уничтожены и созданы заново.
